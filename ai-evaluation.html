Case study · AI evaluation · Making machines trustworthy

Catching the code that's quietly wrong.

This is the other half of what I do. Arzìqi is about trusting your money. This was about trusting what a language model spits out. Concretely: reading AI-generated code and deciding whether it's actually correct.

Role · AI Model Evaluator (LLMs) Anthropic, via Turing Remote

The work

Read AI-generated Rust and judge it. Is it correct, is it complete, could you actually ship it?

The lens

Not "does it look right" but "would a developer put this in production?" Judgment calls, right at the edge of what the model can and can't do.

How I worked

Compare outputs side by side, write up what's wrong and why, and leave notes that feed back into a better model.

The result

Feedback that made the model more reliable and easier for developers to actually work with.

Why it matters

A model that sounds sure of itself but is wrong does real damage. Same problem as Arzìqi, different place.

AI-generated code is where this gets hard. It's fluent, it looks plausible, and it's often quietly wrong. My job was to be the person who can tell the difference, and to do it consistently enough that the feedback is actually worth something. That's what evaluation is: decide what "good" means, then hold everything to it.

What I looked for

Failure mode

Hallucinations

Confident output that invents APIs or behaviour that doesn't exist. The scariest kind, because it reads so well.

Failure mode

Not following instructions

Code that drifts off the task. Solves something nearby, ignores a constraint, quietly changes the ask.

Failure mode

Broken reasoning

Logic that falls apart the moment you actually check it. Right-looking steps that don't add up.

Failure mode

Not quite done

Works in the happy path, but isn't correct or complete enough for someone to really ship it.

How it ties to the product work

Both sides of my work ask the same thing: can you trust what this is telling you? With Arzìqi it's financial data. With the model it's generated code. Either way it comes down to deciding what trustworthy means and caring most about the failures that hide behind a confident surface. Spotting the gap between "looks right" and "is right" is the habit running through all of it.

Two jobs, one habit.
